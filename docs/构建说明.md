# 从源码构建

[返回项目首页](../README.md) · [English introduction](../README.en.md)

应用采用原生 Java，没有第三方运行时依赖。构建脚本直接调用官方 Android SDK 工具，无需 Android Studio 或 Gradle；也可以通过 Android Studio 的 SDK Manager 安装 SDK。

## 准备工具

- Python 3。
- JDK 17 或更新版本。本次维护者构建使用 JDK 26，编译 Java 8 字节码。
- Android SDK Platform 36，即 `platforms/android-36/android.jar`。
- Android SDK Build Tools 36.0.0，包括 `aapt2`、`d8`、`zipalign`、`apksigner`。

工具安装与下载见 [Android SDK 官方页面](https://developer.android.com/tools)。已安装 `sdkmanager` 时，可按 Android SDK 的许可与安装提示安装：

```sh
sdkmanager "platforms;android-36" "build-tools;36.0.0"
```

构建脚本使用 Unix 风格的工具路径，已在 macOS 验证；其他平台未经本项目验证。Windows 原生环境可能需要调整可执行文件扩展名。

## 编译

在仓库根目录运行，路径应指向自己的 SDK 和 JDK：

```sh
python3 build.py --sdk /path/to/android-sdk --jdk /path/to/jdk
```

脚本依次运行 75 项纯 Java 路由检查、资源编译、Java 编译、DEX 构建、ZIP 对齐、APK 签名和验证。最终产物为：

```text
build/Wallet-Bridge-0.1.0.apk
```

测试覆盖精确包名与类名匹配、允许的包名范围、相对类名、异常输入、重复事件和冷却时间边界。它们不替代 ColorOS 设备上的跳转与生命周期测试。

## 签名与更新

首次运行默认在 `build/signing/` 创建个人签名密钥及密码文件。该目录和其他常见签名文件已加入 `.gitignore`，不应提交到任何仓库。

要把签名材料放到仓库之外，可指定自己的持久目录：

```sh
python3 build.py --sdk /path/to/android-sdk --jdk /path/to/jdk --signing-dir /private/path/to/wallet-bridge-signing
```

保留签名材料才能发布可覆盖安装的后续版本。删除默认 `build/signing/` 后重建会产生新密钥。新签名通常无法覆盖安装原签名应用；若选择先卸载再安装，应用内配置会被清除。

GitHub 发布的 APK 使用维护者保留的本地密钥，仓库与 Releases 均不包含私钥或密码。自行构建的 APK 通常拥有不同签名。

## 发布版验证

在 [Releases](https://github.com/yqia03/coloros-wallet-bridge/releases/latest) 下载 APK 和 `SHA256SUMS.txt`，可用 SHA-256 工具检查下载的 APK 与发布时一致。例如 macOS / Linux 中存在相应命令时：

```sh
shasum -a 256 Wallet-Bridge-0.1.0.apk
```

v0.1.0 的发布 APK 来自已经收到用户成功反馈的原始构建；本次仓库整理未修改应用代码或重新替换该 APK。
