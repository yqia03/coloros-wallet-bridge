# 钱包快捷桥 / Wallet Bridge

**简体中文** · [English](README.en.md)

双击电源键后，让 OPPO 钱包快捷页面自动转到 **Google 钱包**。适用于需要保留国行 ColorOS 原有钱包快捷入口的场景，**无需 root，也无需 ADB 授权**。

本项目已收到**国行 OPPO Find X9、未 root 的用户实机成功反馈**。具体其他机型需要测试。

**[下载 APK](https://github.com/yqia03/coloros-wallet-bridge/releases/latest) · [详细使用说明](docs/使用说明.md) · [自行构建](docs/构建说明.md) · [反馈问题](https://github.com/yqia03/coloros-wallet-bridge/issues)**

> 无障碍服务需要保持后台连接；应用界面不必一直打开。用户实测：清理「钱包快捷桥」后台后可能停止跳转。设置完成后直接返回桌面即可，避免清理或强行停止它。

## 能做什么

- 识别指定的 OPPO 钱包页面，随后打开 Google 钱包首页。
- 使用独立应用包名，保留原厂钱包和原有电源键设置。
- 提供中文设置界面、一键测试、暂停开关和页面校准。
- 锁屏时通过系统正常解锁流程继续，不绕过锁屏验证。
- 不截屏、不录屏、不做 OCR，不读取卡片或页面文字，不联网。

## 快速开始

1. 从 [Releases](https://github.com/yqia03/coloros-wallet-bridge/releases/latest) 下载 `Wallet-Bridge-0.1.0.apk`，传到手机安装。
2. 保留手机原有的“双击电源键打开钱包”设置和 OPPO 钱包应用。
3. 打开「钱包快捷桥」，点击 **“1. 测试打开 Google 钱包”**，确认能正常打开。
4. 点击 **“2. 开启无障碍服务”**，阅读用途说明后，在系统设置中开启「钱包快捷桥」。
5. 返回应用，确认“无障碍：已连接”，点击 **“3. 启用自动跳转”**。
6. 返回桌面，双击电源键测试。若仍停在 OPPO 钱包，使用应用里的 **60 秒校准**，保存识别页面后重新启用跳转。

校准、受限制的设置、后台失效与卸载操作见[详细使用说明](docs/使用说明.md)。

## 工作原理

**双击电源键 → 系统打开 OPPO 钱包 → 快捷桥识别指定页面 → 关闭该页面 → 必要时由系统解锁 → 打开 Google 钱包。**

这是页面转发。程序不直接拦截电源键，不修改系统的按键映射，也不替换 OPPO 钱包。

服务只订阅指定钱包应用的窗口状态事件，检查包名和页面类名。平时等待系统通知，不循环扫描屏幕。后台耗电尚未实测，因此没有耗电数值或续航承诺。

## 已知限制

- **后台连接是必要条件。** 清理后台、强行停止或系统关闭无障碍服务后，可能失效。重新打开应用并检查服务状态；重启和系统更新后也应检查。
- **可能闪过原厂钱包。** 本工具使用原厂入口转发，无法保证与系统原生入口一样流畅。
- **同一页面也会触发。** 手动打开被识别的 OPPO 钱包页面同样可能跳转；使用原厂钱包前可先暂停。
- **支付设置独立。** 本工具只打开 Google 钱包首页，不修改默认 NFC 支付应用，不替你付款，不改变设备、卡片或地区的支付支持条件。
- **系统更新可能影响识别。** 原厂页面变化后，可能需要重新校准或更新程序。

## 权限与数据

应用使用用户主动开启的无障碍服务。声明只接收 `TYPE_WINDOW_STATE_CHANGED`，限定以下应用包：

- `com.heytap.tas`
- `com.finshell.wallet`
- `com.heytap.wallet`

实际代码只读取事件的包名和类名，不读取事件文字或屏幕节点。校准最多在本机保存 20 个页面标识，必须由用户确认后才作为跳转目标。

没有网络、系统日志读取、悬浮窗或改写系统设置权限；没有广告、分析 SDK 或第三方运行时依赖。可以在应用内暂停，或关闭无障碍服务、卸载应用来停用。

## 构建与源码

原生 Java 应用，目标 SDK 36，使用 Python 脚本直接调用 Android SDK 工具，无需 Gradle。

```sh
python3 build.py --sdk /path/to/android-sdk --jdk /path/to/jdk
```

需要 Python 3、JDK 17 或更新版本、Android SDK Platform 36 和 Build Tools 36.0.0。构建脚本会执行测试、打包并签名；完整步骤和签名更新说明见[构建说明](docs/构建说明.md)。

发布 APK 使用维护者的本地签名密钥。**仓库不包含私钥、密码、本地 SDK 或构建缓存。** 自行生成的新签名通常不能直接覆盖安装发布版。
